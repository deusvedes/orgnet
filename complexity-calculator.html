How the model works

Each component is normalized to 0–1. Score = 1 + 9 × sum(weight × component) / sum(available weights). Missing measurements are excluded. Availability shows the share of configured weights with usable data, not statistical confidence.

Structural complexity covers code size, dependencies, client candidates, endpoints, packages, method branching, package cycles and coupling. Risk adds coverage shortfall, Boot test density, version policy, code churn and author concentration. Risk bands: LOW below 4, MEDIUM from 4 to below 7, HIGH from 7.

Versions use the lowest declared major. Coverage and author share use percentages (0–100). Churn uses added + removed production Java lines over one consistent Git window. Client and endpoint counts are estimates. Boot test class counts do not measure test quality. Version thresholds are internal policy, without automatic EOL or CVE lookup.
